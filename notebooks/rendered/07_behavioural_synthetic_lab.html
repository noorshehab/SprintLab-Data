NB07 — Behavioural-Diagnosis Synthetic Lab (centerpiece)¶

RQ: RQ2, RQ2.1, RQ2.2, RQ2.4 — can a neural network classify a student's behavioural scenario from response metadata, which metrics operationalise each trait, and are near-identical scores mapped to near-identical treatment plans?

The honesty boundary (NB00). The proxy dataset has NO response time, distractor choice, or cognitive-load field — every behavioural metric in the RQ note is uncomputable from real Noxed-proxy logs. This notebook does NOT pretend otherwise. It builds a parametrised SYNTHETIC generator for the 12 authored student cases, scaffolded on real item difficulty (NB01) so the synthetic sessions are at least grounded in a realistic difficulty distribution, then asks an honest feasibility question: if these metrics could be measured, would the 12 cases actually be separable, or do the RQ note's own confound caveats (impulsivity/anxiety/rapid-guessing entanglement) show up as real classifier confusion? The result is a feasibility study and a minimum-real-data specification, not a validated behavioural classifier.

N_STUDENTS_PER_CASE = 120
N_ITEMS_PER_SESSION = 60
all_cases = behavioural.CASES + ["typical"]

sessions, metrics_rows = [], []
for case in all_cases:
    for s in range(N_STUDENTS_PER_CASE):
        session = behavioural.generate_synthetic_session(rng, case, D_sample, n_items=N_ITEMS_PER_SESSION)
        session["student_id"] = f"{case}_{s}"
        sessions.append(session)
        m = behavioural.compute_metrics(session)
        metrics_rows.append({"case": case, "student_id": f"{case}_{s}", **m})

metrics_df = pd.DataFrame(metrics_rows)
print(f"generated {len(all_cases)} cases x {N_STUDENTS_PER_CASE} students = {len(metrics_df)} synthetic sessions")
metrics_df.groupby("case").mean(numeric_only=True).round(3)

3. Trait separability: can a classifier recover the case from metrics alone?¶

In [4]:
metric_cols = [c for c in metrics_df.columns if c not in ("case", "student_id")]
X = StandardScaler().fit_transform(metrics_df[metric_cols].fillna(0))
y = metrics_df["case"].to_numpy()

clf = RandomForestClassifier(n_estimators=300, max_depth=8, random_state=0)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
y_pred = cross_val_predict(clf, X, y, cv=cv)

per_class_f1 = pd.Series(f1_score(y, y_pred, average=None, labels=sorted(set(y))), index=sorted(set(y))).sort_values()
print("Per-case cross-validated F1 (RandomForest, 5-fold):")
print(per_class_f1.round(3))
print(f"\nmacro-F1: {f1_score(y, y_pred, average='macro'):.3f}")

Reading the confusion matrix. Watch specifically for the confound the RQ note predicts: impulsiveness (fast + wrong) vs. any case with elevated fast-error patterns, and stress_overthinking vs. weak_prior_knowledge (both show elevated time + errors, differing only in WHEN they occur). If those specific pairs show elevated off-diagonal mass while well-separated pairs (e.g. impulsiveness vs. time_management_perfectionism, opposite-direction tau effects) stay clean, that is exactly the theoretically-predicted confound structure — a sign the simulation is behaving sensibly, not randomly.

5. Score-to-plan smoothness (RQ2.4)¶

In [7]:
thresholds = {
    "fast_error_rate": {"case": "impulsiveness", "cutoff": 0.4},
    "carelessness": {"case": "misconceptions", "cutoff": 0.3},
    "negation_error_gap": {"case": "question_interpretation", "cutoff": 0.15},
    "context_switch_cost": {"case": "cognitive_flexibility", "cutoff": 0.1},
    "cognitive_load_sensitivity": {"case": "working_memory", "cutoff": 0.1},
    "end_of_match_decay": {"case": "attention", "cutoff": 0.1},
    "pressure_sensitivity": {"case": "stress_overthinking", "cutoff": 0.1},
}

smoothness_rows = []
sample = metrics_df.sample(min(200, len(metrics_df)), random_state=0).reset_index(drop=True)
for i in range(len(sample) - 1):
    a, b = sample.iloc[i], sample.iloc[i + 1]
    scores_a = {k: a[k] for k in metric_cols}
    scores_b = {k: b[k] for k in metric_cols}
    plan_a = behavioural.score_to_plan(scores_a, thresholds)
    plan_b = behavioural.score_to_plan(scores_b, thresholds)
    smoothness_rows.append(behavioural.plan_smoothness(scores_a, scores_b, plan_a, plan_b))

smooth_df = pd.DataFrame(smoothness_rows)
corr_smoothness = smooth_df["score_l2_distance"].corr(smooth_df["plan_jaccard_distance"])
print(f"corr(score distance, plan distance) = {corr_smoothness:.3f}  "
      f"(positive & significant => nearby scores get nearby plans, as RQ2.4 requires)")

fig, ax = plt.subplots(figsize=(6, 4.5))

Findings → consumed by¶

  • outcomes/trait_separability.csv → Behavioural NN design: cases with low synthetic-F1 need EITHER additional real signal (response time / distractor choice — confirmed absent, NB00) or a merged/coarser class definition before a live model ships.
  • outcomes/synthetic_behavioural_metrics.csv is a ready-made pre-training set for the NN's architecture search, standing in for real data during cold start (RQ5).
  • The smoothness correlation is direct evidence for/against RQ2.4's design assumption.
  • Central caveat, restated: every number in this notebook describes the SIMULATION's internal consistency, not real students. Treat it as a feasibility and instrumentation spec, not a validated classifier.
